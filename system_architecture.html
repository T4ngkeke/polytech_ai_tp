Zero-Friction

Invite Code Workflow

The tedious manual approval process is replaced with 6-character Invite Codes. Students can instantly join a class and access their assigned labs, ensuring a flawless and fast demo experience.

Granular Control

Three-Tier Rule Injection

The Prompt Controller dynamically fetches and sequentially merges rules from three levels: Class Rule -> Lab Rule -> Student Rule, injecting highly targeted pedagogy directly into the LLM context.

Zero-Downtime

Dynamic LLM Configuration

Crucial LLM connection details (Base URL, API Key, Model) are now fetched from the SystemConfigs database table rather than a static .env file. Admins can hot-swap AI models on the fly.

Context Safe

Lab-Scoped Sessions

Chats are no longer infinite global threads. Students create isolated Chat Sessions inside a specific Lab. This clears history safely, preventing catastrophic Context Window overflow for smaller local models.

Database Schema (PostgreSQL)

Table Status Core Fields Purpose
system_configs New id, key, value Database-driven configuration for LLM connections, allowing live model hot-swapping.
classes & labs New invite_code, teacher_id, class_id Hierarchical structure for organizing students. Uses invite_code for instant join.
rules Modified level, target_id, rules_text Replaces old teacher_rules. Uses polymorphism to store Class, Lab, and Student-specific AI rules.
sessions Modified id, user_id, lab_id Tightly scoped to a lab_id. Allows clearing history to avoid LLM context overflow.
users Unchanged id, role, daily_token_quota Supports bulk creation via Admin CSV dry-run import.
