System architecture

Edu-LLM: a course tutor that answers from the teacher's PDFs

Teachers upload course PDFs to a class or a lab. Students ask questions in a chat. The model answers from those PDFs and cites the pages it used.

This page draws what runs today. The details are in ARCHITECTURE.md, the endpoints in API.md and the tables in DATABASE.md.

1. What runs

Five kinds of containers. The browser only talks to nginx. The backend and the worker share one database and the same model servers. The database table ingestion_jobs is the job queue; there is no other queue.

2. How a question is answered

There is one chat path, the research agent in backend/app/agent/. The student picks a mode. A class in exam mode always gets Direct. Search and Research only cite what was read in this run.

3. How a PDF becomes searchable

An upload never changes what students see until a revision is published. A teacher edit makes a new draft; it never changes a published revision.

4. Design rules

The choices that the rest of the code relies on.

Access is checked in SQL

Every course search filters on class_id, lab_id and the revisions fixed at the start of the run. A prompt cannot widen it. The model never sends a file address.

Citations only from what was read

Only what the model read (read) or looked at (view_image) gets an evidence ID. Search results are leads, not proof. An answer may cite only those IDs.

Search in one table

A vector search (pgvector) and a full-text search (tsvector) run on the same passages. The two lists are merged, then the reranker orders them. If the embedding server fails, the full-text list is used alone.

One model, set in the database

Qwen3.8 Flash-Next answers, looks at pictures and writes figure descriptions. Model addresses are rows in system_configs; the admin changes them without a restart.

The database is the queue

The worker takes jobs with FOR UPDATE SKIP LOCKED and a lease. It waits while students chat, so reading PDFs never slows down answers.

Tokens are reserved, then billed

Each model call is reserved on the daily quota before it runs and billed after, as prompt × 0.2 + completion × 1.0 by default. A teacher can refill a student's quota for the day; usage figures are never rewritten.

Teacher rules shape the tutor

Class, lab and student rules go into every answer mode. They set the teaching style. They are not a security boundary; access is checked in SQL.

Nothing a student deletes is lost

A deleted session is hidden from the student but kept. Teachers and admins still see it. Only an admin can delete it for good.

Grafana for admins only

For every /grafana/ request, nginx asks the backend to check the admin's signed cookie. Students on the network cannot read other students' questions.

5. Where the data lives

The tables in groups. Every table and column is in DATABASE.md.

Group Tables What they hold
Settings system_configs Model addresses and names, token weights, research limits.
People and classes users, classes, labs, class_students Roles, daily quota, invite codes, exam mode, who is in which class.
Rules rules, skill_presets Teacher rules at class, lab and student level; reusable teaching styles.
Chat sessions, messages, message_citations, agent_runs Conversations, answers with their mode and feedback, cited passages, one row per research run.
Usage usage_stats, quota_grants, usage_reservations, model_call_usage Tokens per user and day, teacher refills, reserved and billed model calls.
Reports audit_reports AI reports on a lab or one student, written from counted numbers.
Documents documents, document_revisions, document_pages, document_blocks, document_assets, document_reviews, … Each upload, each reading of it, its pages, blocks and pictures, and the items a teacher confirms.
Search doc_chunks The passages, with their embedding and full-text vector.
Queue ingestion_jobs Read and index jobs, with lock, lease and progress.

6. Two stacks, one code base

Teachers' stack

docker-compose.release.yml: its own database, files and daily backup, served over HTTPS on the school network. It is updated only by rebuilding it. See RELEASE_TEACHERS.md.

Dev stack

docker-compose.yml with docker-compose.override.yml: feature flags on, site on port 8080, and the monitoring containers. Grafana serves both stacks.

Shared model servers

Both stacks call the same model servers on the Docker network edullm-models.
