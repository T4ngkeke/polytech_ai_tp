Architecture v8.0 — Agentic Class-Lab Architecture

Edu-LLM: Agentic RAG, Hybrid Retrieval & Off-Peak Ingestion

The v6 foundation (3-tier RBAC, invite codes, hierarchical rule injection) plus a LangGraph agent and the v7.1 retrieval core (PDF-only structured ingestion with Contextual Retrieval, hybrid vector + BM25 retrieval with reranking, a bounded LLM self-eval loop). v7.2 adds a full config-driven model-routing table (split a cheap off-peak ingestion / live router model from the expensive chat model), cost-aware weighted-token quota, an LLM-assisted exercise-number fallback with canonical normalization, per-teacher skill presets, section-scoped (length-safe) Contextual Retrieval, and a markdown / code-highlight / KaTeX student chat UI — plus self-service password change. v7.3 hardened the data pipeline (single-source deterministic exercise segmentation, strict CM/TD-TP split, language-aware OR-semantics BM25). v8.0 replaces the kNN router with a one-call LLM router carrying dialogue state (a sticky exercise fills a blank number but never picks the route; unresolvable numbers ask a clarifying question), adds a teacher-driven hint lifecycle (ingestion never generates hints; a teacher triggers generation, reviews per-exercise, and only approved hints reach students), stores uploaded answers in a main-DB Answers table for offline hint generation (the student path never imports the Answer model), and adds the human loop — teacher test-drive, student feedback, an admin health panel, and a teaching-hotspot panel.

📌 Status: the v8.0 backend is shipped (branch v7.2-upgrade); the v8.0 frontend and the retrieval golden-set eval are still in progress. Authoritative design log: V8.0_PLAN.md + v8_workflow.html.

Agent, not Proxy

LangGraph Agentic RAG

The chat endpoint is a graph: router → [exercise → tutor | rag | direct | clarify] → self-eval loop → Synthesize → SSE. [v8.0] the router is one LLM call per message that classifies the route AND carries dialogue state: a sticky exercise (from session.current_exercise_id) fills a blank number but never picks the route, and an unresolvable number produces a clarifying question rather than a wrong-exercise guess. Timeout/failure degrades to a safe rag and is flagged. This replaced the v7.1 regex + bge-m3 kNN exemplar router.

Single DB

Hybrid Retrieval on pgvector

Concept questions hit hybrid RAG — vector ANN and BM25 (tsvector) recall → RRF fusion → bge-reranker-v2-m3; exact missions hit structured search over exercises. All retrieval is filtered by lab_id/class_id (and audience for students) in SQL. No solution is stored anywhere — nothing to leak.

Off-Peak · GPU-Aware

Ingestion Worker (No Airflow / k8s)

A docker-compose worker polls ingestion_jobs (SKIP LOCKED) and runs guided-JSON extraction at low priority on the same engine. A pynvml gate only pulls work when the GPU is idle; chat always preempts.

One Shared Engine

Config-Driven Model, Never Hardcoded

Chat and ingestion call the same existing engine (vLLM/Ollama) and the one model set in SystemConfigs — no second model, nothing hardcoded. Swap to any model that fits the box (e.g. smaller for test, larger for prod) with zero downtime and no code change.

Granular Control

Three-Tier Rules + skill.md

skill.md (instructor persona) reuses the Rules table as a level=class rule placed first (sets tone); restrictive Class → Lab → Student rules come after so constraints win, resisting prompt-injection bypass.

Zero-Friction · Context Safe

Invite Codes & Lab-Scoped Sessions

Retained from v6: 6-character invite codes for instant class joining, and isolated chat sessions scoped to a single Lab — clearing history safely and preventing context-window overflow on smaller local models.

Teach Prompt Literacy

Effort Coaching, not Mastery Grading

Two cheap rules-first signals (no LLM): a windowed effort/clarity score gently coaches how to ask (never gates a "stupid" question), and a per-message lazy / answer-seeking detector forces a Socratic reply — it answers, but never hands over the answer. Structured scores only, teacher-overridable.

v7.1 · Context-Poor Slides

Contextual Retrieval at Ingest

The off-peak worker LLM-generates each chunk's in-document context and prepends it; the augmented text (context + content) is embedded and BM25-indexed, while the original content is kept for citation. This is what makes context-poor CM slides retrievable. Same engine as chat, config-driven, no torch.

v7.1 · Bounded & Cheap

LLM Self-Eval Loop

A deterministic gate (cosine / empty recall) blocks the obviously-bad before any LLM; a guided 1-token verdict grades good / partial / bad; a bad verdict rewrites the query and re-retrieves, capped at RAG_MAX_RETRIES (admin-config, default 1). Still thin after the budget → answer with a "not enough material" disclaimer.

v7.2 · Split the Engine

Full Model-Routing Table

Generation, embedding, rerank, ingestion, and router each get an optional endpoint/key/model in SystemConfigs. Ingest/router default empty → fall back to the main LLM, so the cheap-model split is opt-in: a 120B serves chat while a 30B does off-peak Contextual Retrieval and live router intent — without sharing one RPM pool.

v7.2 · Cost-Aware

Weighted-Token Quota

Prefill is cheaper than decode, so quota is now charged on billed = prompt·α + completion·β (admin-set TOKEN_ALPHA/TOKEN_BETA, default 0.2/1.0). Raw prompt/completion counts are still stored per message; the 429 check and /usage compare billed tokens to the daily quota.

v7.2 · Stable Matching

LLM-Assisted Exercise Routing

The deterministic exercise-number regex stays the zero-latency fast-path; only when it misses but the query looks exercise-shaped does a cheap ROUTER_MODEL disambiguate. A canonical number_normalized integer (Roman / Arabic / 3.1 all map to one number) lets ingest extraction and query matching share one normalization function.

v7.2 · Instructor Style

Per-Teacher Skill Presets

Teachers keep a private library of reusable skill presets and snapshot-copy one into a class's level=class rule. The prompt-injection path is unchanged (still reads Rules); editing a preset never retro-changes classes that already selected it.

v7.2 · Context-Poor, Length-Safe

Section-Scoped Contextual Retrieval

Per-chunk context is generated from the chunk's own scope — its section (TD/TP) or page/slide (CM) — instead of full_text[:8000], so a long document never gets a context hallucinated from its opening pages, and the call fits any small model. No hard length gate; long docs simply degrade to per-slide context, all on the off-peak INGEST_MODEL.

v7.2 · Student UX

Markdown + Code + KaTeX Chat

The student chat renders markdown, syntax-highlighted code blocks (with copy), and KaTeX math, using stream-safe incremental rendering so a half-streamed fenced block never collapses into plain text. Plus self-service password change for every role.

v7.3 · Deterministic Ingestion

Single-Source Segmentation + Strict Split

Headers/footers stripped and TOC removed once for the whole pipeline. TD/TP exercises are built deterministically from expanded boundary patterns (Arabic / Roman / Question n / bare-numbered headings): number = the captured label, statement = the segment body — the whole-document LLM extractor (root cause of wrong numbers) is deleted. An LLM re-judges boundaries only on numbering anomalies (1,1,2,3 = sub-questions mistaken for exercises); its failure keeps the regex result. Strict split: TD/TP never produce RAG chunks; DocChunks come from CM only. Teacher edits survive re-ingestion; a per-document ingest_report gives the teacher a warning list.

v7.3 · Retrieval Fixes

BM25 Revived + Honest Reranking

The BM25 leg was silently dead: simple config + AND semantics meant one extra word in a natural French question zeroed the recall. Now OR semantics over content words with per-document language configs (fr/en, stemming: "fonction" matches "fonctions"), same config at ingest and query time. The reranker scores the augmented text (context + content) instead of vetoing the context-poor slide chunks Contextual Retrieval was built to save. A RERANK_SCORE_THRESHOLD injection gate is wired in the retrieval layer and ships disabled until calibrated — its zero-context disclaimer branch lands in v8.0. CM chunks get size control (120–1600 chars) with code-aware splitting.
