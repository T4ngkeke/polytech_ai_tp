Architecture v7.1 — Agentic Class-Lab Architecture

Edu-LLM: Agentic RAG, Hybrid Retrieval & Off-Peak Ingestion

The v6 foundation (3-tier RBAC, invite codes, hierarchical rule injection) plus a LangGraph agent. v7.1 upgrades the retrieval core: PDF-only structured ingestion with Contextual Retrieval, a multilingual embedding-kNN router, hybrid (vector + BM25) retrieval with reranking, and a bounded LLM self-eval loop — all on a GPU-aware off-peak worker. Chat and ingestion share one existing inference engine (vLLM/Ollama); the model is config-driven via SystemConfigs, never hardcoded — swap any model that fits the box with zero downtime.

Agent, not Proxy

LangGraph Agentic RAG

The chat endpoint is a graph: Router → [agentic_search | rag | direct] → self-eval loop → Synthesize → SSE. The router is cheap and multilingual — a deterministic exercise-number regex fast-path, then bge-m3 cosine-kNN over in-code anchor exemplars — avoiding pure ReAct so slow-bandwidth decodes aren't wasted on every step.

Single DB

Hybrid Retrieval on pgvector

Concept questions hit hybrid RAG — vector ANN and BM25 (tsvector) recall → RRF fusion → bge-reranker-v2-m3; exact missions hit structured search over exercises. All retrieval is filtered by lab_id/class_id (and audience for students) in SQL. No solution is stored anywhere — nothing to leak.

Off-Peak · GPU-Aware

Ingestion Worker (No Airflow / k8s)

A docker-compose worker polls ingestion_jobs (SKIP LOCKED) and runs guided-JSON extraction at low priority on the same engine. A pynvml gate only pulls work when the GPU is idle; chat always preempts.

One Shared Engine

Config-Driven Model, Never Hardcoded

Chat and ingestion call the same existing engine (vLLM/Ollama) and the one model set in SystemConfigs — no second model, nothing hardcoded. Swap to any model that fits the box (e.g. smaller for test, larger for prod) with zero downtime and no code change.

Granular Control

Three-Tier Rules + skill.md

skill.md (instructor persona) reuses the Rules table as a level=class rule placed first (sets tone); restrictive Class → Lab → Student rules come after so constraints win, resisting prompt-injection bypass.

Zero-Friction · Context Safe

Invite Codes & Lab-Scoped Sessions

Retained from v6: 6-character invite codes for instant class joining, and isolated chat sessions scoped to a single Lab — clearing history safely and preventing context-window overflow on smaller local models.

Teach Prompt Literacy

Effort Coaching, not Mastery Grading

Two cheap rules-first signals (no LLM): a windowed effort/clarity score gently coaches how to ask (never gates a "stupid" question), and a per-message lazy / answer-seeking detector forces a Socratic reply — it answers, but never hands over the answer. Structured scores only, teacher-overridable.

v7.1 · Context-Poor Slides

Contextual Retrieval at Ingest

The off-peak worker LLM-generates each chunk's in-document context and prepends it; the augmented text (context + content) is embedded and BM25-indexed, while the original content is kept for citation. This is what makes context-poor CM slides retrievable. Same engine as chat, config-driven, no torch.

v7.1 · Bounded & Cheap

LLM Self-Eval Loop

A deterministic gate (cosine / empty recall) blocks the obviously-bad before any LLM; a guided 1-token verdict grades good / partial / bad; a bad verdict rewrites the query and re-retrieves, capped at RAG_MAX_RETRIES (admin-config, default 1). Still thin after the budget → answer with a "not enough material" disclaimer.
