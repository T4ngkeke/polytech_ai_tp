# Edu-LLM v7.1 — Plan

> **Context.** v7 (agentic RAG, ingestion worker, prompt-literacy tutoring) is built and
> backend-tested (230 tests). The current RAG path is still **naive**: fixed-size chunking →
> embed → dump into pgvector, with a **rules/regex router** (brittle for multilingual
> students). v7.1 leads with a **retrieval-quality + agentic upgrade**; the admin-oversight
> and broader frontend work stay **deferred** (bottom) — except a teacher ingestion-visibility
> slice, now **pulled forward** as Phase 1's acceptance surface (Phase 6).
>
> **Decisions locked (this round):**
> - Router: regex → **multilingual embedding-kNN** (reuse bge-m3), BERT later.
> - Pipeline: **structure-aware chunking + Contextual Retrieval + hybrid (vector+BM25) + rerank.**
> - Online: **LLM self-eval + bounded agent loop** — go all-in now (60 tps budget accepted).
> - GPU: keep **one resident model + off-peak low-priority batching** (no load/unload swap).
> - **Input = PDF only.** Instructors export slides (.ppt/.pptx) → PDF themselves before upload.
>   No LibreOffice/python-pptx in the worker, **no OCR** — extraction is pymupdf + a cheap
>   character-yield gate; unreadable files are rejected back to the teacher (`needs_review`).
> - **Drop the corrigé entirely.** A 120B (GPT-OSS / Qwen3.5) solves this exercise level itself, so
>   we do **not** ingest solutions and **drop the `Exercise.solution` column**. Store **exercise
>   statements only.** This deletes the entire solution-leak red line — our single largest risk surface.
> - **Anything the teacher needs** (course conventions/method, or a specific non-derivable answer)
>   goes in the **class-level prompt** (3-tier injection) — *not* a per-exercise field, *not* an
>   ingested corrigé. Discipline: the class prompt holds **conventions, not a full answer key**
>   (a full key bloats the resident prompt and re-creates a soft leak surface).
>
> **Red lines (revised):**
> - **Tenant isolation** (`lab_id`/`class_id`) enforced in the **SQL WHERE clause, never in the
>   prompt** — prompt-injection cannot break a query filter.
> - **No corrigé ingestion.** Solutions are not stored anywhere; statements only. (Nothing to leak.)
> - **Security in the database, pedagogy in the prompt.** The Socratic guardrail is a *behavioral*
>   guardrail — if a clever student jailbreaks it the harm is low (the model could derive that
>   answer anyway, and there is no stored answer key). Security boundaries must **never** degrade
>   into a prompt guardrail.
> - Structured-only governance (controlled vocabulary, no free-text judgments about students).

## Data reality

Four document types drive every routing/parsing decision. **Type is known at upload → it is the
deterministic router signal; we do not guess structure.**

| Type | Nature | Role |
|---|---|---|
| **CM slides** | dirty, **most common**, fragmentary (each slide = context-poor) | main workload; Contextual Retrieval is what makes it retrievable |
| **CM book** | clean, **rare** (most instructors don't write one) | golden smoke-test fixture — **not** the architecture template |
| **TD** | exercises (problem sets) | exercise-statement extraction |
| **TP** | exercises **+ code** | exercise extraction; code blocks must stay intact |

- **Input = PDF only.** Slides are exported to PDF by the instructor (1 slide = 1 page). This
  collapses ingestion to a single pymupdf path — no `.ppt` parsing, no LibreOffice in the worker.
- **Verified:** the three sample PDFs (TD / TP / CM_book) are digital-born with clean, selectable
  text (600–2100 chars/page) and visible heading structure. "Very dirty PDF" was an overestimate;
  pymupdf handles them directly. Only embedded figures need to be skipped/handled.
- **Corrigés exist as separate teacher documents** — but we **do not ingest them** (see decision above).

---

## Goal

Upgrade RAG from "naive chunk-and-dump + keyword routing" into **PDF-only structured ingestion +
multilingual routing + high-quality hybrid retrieval + LLM-self-eval bounded agent loop**, on a
local 120B at ~60 tps, without breaking the governance red lines.

## Guiding principles

- Mechanical steps stay deterministic; reserve LLM agency for the real "judgment" joints
  (e.g. parsing clean structure is mechanical; Contextual-Retrieval context generation is judgment).
- **Ingestion decides retrieval quality → pipeline goes first.**
- **Don't let the one clean doc (CM book) define the data model.** Design for CM slides (the
  dominant, fragmentary case); use CM book only as the end-to-end skeleton / smoke fixture.
- Self-eval: the *grade* must be cheap (guided, short output); the *re-loop* must be bounded (≤1).
- Cheap deterministic gates first; LLM self-eval only on the genuinely ambiguous cases.
- **Security in SQL, pedagogy in the prompt** (see red lines).

## Phase 1 — Ingestion pipeline rework (main work, first)

> Deps: Phase 0. This is the source of whether hybrid/loop later have any decent material.

| # | Task | Key point | Done when |
|---|---|---|---|
| 1.0 | **Parsing & input gate** | **PDF only** → pymupdf text extraction; **no OCR**. Cheap **character-yield gate** (chars/page below threshold, or high garbage/non-word ratio) → mark `needs_review` and reject back to the teacher; **never silently ingest garbage** | clean PDFs parse; bad PDFs flagged, not ingested |
| 1.1 | **Type + audience routing** | route by upload metadata (`CM/TD/TP`, `student/teacher`) — deterministic, no structure guessing; decides chunk-path vs exercise-path and whether Contextual Retrieval applies | routed by metadata, unit-tested |
| 1.2 | **Structure-aware chunking** | split on heading/paragraph/exercise boundaries; **never cut an exercise or a code block in half**; **detect & drop the TOC** (table des matières) — else it matches every query and pollutes recall | exercises/code intact; TOC excluded |
| 1.3 | **Contextual Retrieval** | per-chunk, LLM-generate the chunk's in-document context, prepend before embedding; original text still stored. **Load-bearing for CM slides** — a lone slide is a context-poor fragment and is otherwise unretrievable | embedded chunk carries context; slides retrievable |
| 1.4 | **Exercise extraction — statements only** | extract `number / statement / hints` for agentic "exercise N" lookup. **`solution` is NOT extracted or stored — drop the `Exercise.solution` column.** Statements are student-visible → no red-line risk. Any residual instructor need (conventions, a specific non-derivable answer) goes in the **class prompt**, not a per-exercise field | exercises queryable; `solution` column removed |
| 1.5 | **Build BM25 column (tsvector)** | built at ingest time, or hybrid is impossible at query time | chunk has full-text index |
| 1.6 | Metadata enrichment | type / audience / section / page_no / reserved `concept` | fields populated |
| 1.7 | Idempotent re-index verify | full-corpus rerun after strategy change | rerun is consistent |

- **Red line:** no corrigé is ingested; there is no `solution` to leak. (Replaces the old
  "solution never enters a chunk" rule — now enforced by *not storing it at all*.)
- **Cost:** 1.3's per-chunk LLM calls run entirely on the **off-peak worker** — never preempts students.

## Phase 4 — LLM self-eval + bounded agent loop (the close)

> Deps: Phase 1+3 (re-retrieval is only worth it if there's better material to fetch).

| # | Task | Key point | Done when |
|---|---|---|---|
| 4.1 | **Cheap gate first** | cosine threshold / empty-recall blocks the obviously-bad before any LLM | bad cases skip LLM |
| 4.2 | **LLM retrieval self-eval (guided)** | only the ambiguous; controlled-vocab 1–3 token verdict; grade all chunks in one batched call | verdict output is short |
| 4.3 | **Bounded loop** | fail → rewrite query, re-retrieve, **max 1 round**; still fail → degrade to direct answer | never exceeds 1 round |
| 4.4 | **(optional) post-gen grounding eval** | high-risk only; on fail prefer a disclaimer over regenerating | no full-answer rewrite |
| 4.5 | tool-call guided decoding | loop depends on stable tool calls | no malformed JSON |

- **Gate:** 4.5 local-MoE tool-calling stress test must pass before opening the loop.
- **Why guided + bounded:** at 60 tps the *grade* is ~free (short output); the expensive part is a
  **re-generation**, so cap the loop at 1 round and keep grades guided/short.

## Phase 6 — Teacher ingestion visibility (pulled forward from deferred)

> Deps: Phase 1. This is Phase 1's **acceptance surface**, not UI polish: the instructor authored
> the doc, so **the author is the ground-truth oracle** for "was this processed well?" — and their
> review **doubles as the quality-feedback / labeling signal** that feeds the Phase 0.4 eval set.

| # | Task | Key point | Done when |
|---|---|---|---|
| 6.1 | `GET /api/teacher/labs/{lab_id}/documents` | list + status (`pending/processing/indexed/failed/needs_review`) + summary (pages / chunks / exercises) + warnings | list renders with status |
| 6.2 | `GET /api/teacher/documents/{id}/chunks` | paginated chunk text + page_no — **the core "is it well processed?" surface** | instructor can read actual chunks |
| 6.3 | `GET /api/teacher/documents/{id}/exercises` | extracted `number / statement` (no solution exists) | exercises listed |
| 6.4 | **DocumentManager (frontend)** | list (status badges + summary chips + warning icons) → detail (processing report + **chunk inspector**, code blocks shown clearly); poll list for `pending→indexed` | instructor reads chunks, sees report |

- Minimal viable version: a document list (status + summary) + a detail page that scrolls the
  actual chunks. No fancy charts first — let the author *read what got indexed*.

## Build order (incremental)

1. **CM book (clean PDF)** → wire the end-to-end vertical slice (ingest → chunk → embed → retrieve →
   answer) + stand up the eval harness. Goal: a running baseline + a measuring stick, not pretty output.
2. **TD / TP / CM_book PDFs** → main parsing (1.0) + structure-aware chunking (1.2) + type/audience
   routing (1.1) + statement-only exercise extraction (1.4).
3. **Contextual Retrieval (1.3)** → biggest payoff on slides.
4. **Teacher visibility (Phase 6)** → acceptance + feedback loop.
5. **Slides**: handled by the *"export to PDF"* upload rule — **no worker conversion work**. A single
   deck can be manually exported to test slide retrieval without any plumbing.
